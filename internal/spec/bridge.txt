
# SPEC workflow bridge (new configurations only)
context: |
  SPEC guides intent, design review and bounded implementation checkpoints.
  Keep accepted project intent separate from suggestions and assumptions.
  OpenSpec owns canonical specs and each change's proposal, design and tasks.
  Review that same design in a fresh context where available.
  Use real production logic for fast state/action tests; their format is optional.
  Preserve relevant UI, integration and final CI checks.
  Tie evidence to its inputs; archive is not proof of publication or deployment.
rules:
  proposal:
    - State the user outcome, scope, non-goals and relevant risk.
  design:
    - Reference actual code and boundaries, alternatives and verification.
  tasks:
    - Use small checkpoints linked to observable requirements and checks.
operations:
  apply:
    guidance:
      - Follow SPEC checkpoints and retain relevant project-native checks.
  archive:
    guidance:
      - Report remaining evidence gaps; distinguish implementation and release.
